# Политика безопасности

## Поддерживаемые версии

До первого выпуска с тегом исправления безопасности принимаются для текущей
ветки `main`. После выпуска поддерживаются `main` и последняя опубликованная
серия `0.1.x`. Старые снимки разработки могут потребовать повторной подготовки
артефактов и не получают автоматическую миграцию на месте.

## Как сообщить об уязвимости

Используйте **Security → Report a vulnerability** в репозитории GitHub. Это
создаёт приватное уведомление о безопасности и не раскрывает детали публично.

Если приватные отчёты об уязвимостях ещё не включены, не создавайте открытое
обращение. Свяжитесь с сопровождающим приватно через контакт в его профиле
GitHub и запросите безопасный канал для отчёта.

Укажите:

- затронутую версию или коммит;
- минимальные шаги воспроизведения;
- ожидаемые последствия;
- безопасное подтверждение концепции, если оно необходимо;
- возможное исправление или способ снижения риска.

Не отправляйте реальные учётные данные, приватные ключи, мнемонические фразы,
полный `.env`, дампы частного индексера или чужие персональные данные.
Используйте фиктивные или отозванные значения.

## Что считать проблемой безопасности

- обход защит localhost, Host/Origin, CSRF или ограничения размера запроса;
- обход пути или произвольное чтение локальных артефактов;
- попадание секрета, адреса сервера, необработанной трассировки ошибки или
  крупных артефактов выполнения в браузер, API либо журнал;
- небезопасная десериализация или выполнение пользовательского кода;
- нарушение целостности или публикации артефактов, полномочий заданий либо
  границ привилегий;
- уязвимость зависимости с применимым путём эксплуатации.

Об обычных ошибках стратегии, вопросах конфигурации и запросах функций можно
сообщать через шаблоны обращений.

## Примечание по развёртыванию

Control API должен оставаться на `127.0.0.1`/`::1`. Удалённый доступ допустим
только через аутентифицированный обратный прокси TLS или туннель VPN/SSH. Доступ
к ClickHouse только для чтения без проверенного TLS или туннеля требует
отдельного локального явного разрешения; этот флаг не делает соединение
безопасным.
