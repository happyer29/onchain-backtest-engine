# Руководство по Web UI

**Язык:** [English](ui-guide.md) · Русский · [简体中文](ui-guide.zh-CN.md)

Здесь описан полный рабочий процесс в браузере. Все скриншоты сделаны на
изолированных синтетических fixtures: показанные идентификаторы и результаты
не являются данными реального источника или рекомендуемыми параметрами.

## Открытие интерфейса

Из корня проекта запустите локальный сервер:

```bash
backtest serve --config configs/local.toml
```

Откройте `http://127.0.0.1:<control.port>`. Внизу боковой панели раскройте
**Settings** и выберите русский язык или оформление. Для знакомства без запуска
заданий используйте [статическое демо](demo.ru.md).

## 1. Начните с Overview

![Обзор рабочего пространства: навигация, ресурсы, результаты и задания](assets/ui-overview.png)

Назначение разделов боковой панели:

| Раздел | Для чего он нужен |
| --- | --- |
| **Overview** | Ресурсы компьютера, последние проверенные результаты и задания. |
| **Prepare data** | Проверка настроенного источника и публикация ограниченных локальных снимков. |
| **Launch strategy** | Разрешение и постановка в очередь Sniping, Copy Buy или FirstSwap. |
| **Job queue** | Прогресс, события, отмена и допустимый повтор задания. |
| **Strategy results** | Завершённые прогоны, сравнение и сделки. |
| **Models and features** | Последовательность point-in-time ML-артефактов. |
| **On-chain research** | Подписывающие кошельки, совместные покупки и исходные сделки. |
| **Artifacts and lineage** | Проверка артефактов и полного графа зависимостей. |
| **Resources** | Текущие лимиты допуска по памяти, диску и процессам. |

Зелёная метка **Local execution** означает соединение с локальным Control API,
но не подтверждает настройку или допустимость внешнего источника.

## 2. Подготовьте проверенные данные

![Страница подготовки данных с проверкой источника и ограниченным диапазоном](assets/ui-prepare-data.png)

Идите сверху вниз:

1. В **Source inspection** выберите логический ID источника и нажмите
   **Inspect source**. Проверка ограниченная и только для чтения.
2. Перенесите полученные ID inspection и capability в форму плана.
3. Задайте небольшой полуоткрытый диапазон: начало входит, конец не входит.
4. Отправьте подготовку. Тяжёлая работа появится в **Job queue** и не
   выполняется внутри HTTP-запроса.
5. После `SUCCEEDED` откройте receipt или **Artifacts and lineage** и скопируйте
   точные ID Snapshot/ReplayPack для следующих форм.

Не вводите в UI пароль, приватный ключ, произвольный SQL или путь к файлу.
Секреты источника настраиваются локально по [инструкции](configuration.ru.md).

## 3. Запустите стратегию

![Форма Copy Buy с выбором стратегии и раскрываемыми группами параметров](assets/launch-strategy.png)

1. Откройте **Launch strategy** и выберите **Pump.fun Sniping**, **Pump.fun Copy
   Buy** или **FirstSwap**.
2. В **Data and strategy** укажите точные ID артефактов и торговую пару,
   требуемые выбранным контрактом.
3. Проверьте **Entry and exit**. Единицы указаны в подписях: atomic amounts,
   basis points, число транзакций или секунды.
4. Раскройте разделы аккаунтов, комиссий, воспроизводимости и ресурсов. Значения
   по умолчанию являются примерами, а не рекомендациями.
5. Нажмите **Run strategy**. UI проверит поля, разрешит неизменяемую
   спецификацию и покажет receipt очереди.
6. Перейдите по **Open queue**. Успешная отправка ещё не означает успешный
   результат: дождитесь `SUCCEEDED` и откройте опубликованный output.

Синтетический или виртуальный settlement помечается явно и не доказывает, что
аналогичная продажа могла бы исполниться ончейн.

## 4. Следите за заданием в Job queue

![Очередь с фильтром статуса, поиском, результатами и событиями](assets/ui-job-queue.png)

- Фильтр состояния отделяет ожидающие, выполняющиеся, завершённые и ошибочные задания.
- **Events** показывает сохранённый прогресс и точную типизированную ошибку.
- **Cancel** доступен только в состоянии, допускающем отмену.
- **Retry** создаёт новую попытку той же неизменяемой команды и не подменяет входы.
- Ссылка на результат появляется только после публикации проверенного артефакта.

Страница обновляется автоматически, пока вкладка видима. После возвращения из
фоновой вкладки используйте **Refresh**.

## 5. Прочитайте результаты стратегии

![Проверенный результат стратегии со сводкой, вкладками и графиками](assets/strategy-results.png)

1. Проверьте метку **Verified result**, стратегию, сеть и предупреждение о
   fidelity или синтетическом исполнении.
2. Прочитайте сводные карточки. Тире означает «нет данных», а не ноль.
3. **Overview** содержит итоги, **Entries** и **Exits** — решения, **Trades** —
   исполнения, **Verification** — происхождение результата.
4. В **Verification** откройте manifest и lineage перед сравнением прогонов с
   разными входами.
5. Кнопка **Details** у сделки открывает исполнения и ограниченную историю рынка.

![График сделки с сигналом, покупкой и продажей](assets/trade-detail.png)

**Around trade** приближает участок, **Full history** использует ту же сохранённую
ограниченную историю. Наведите курсор на точку для точного значения и раскройте
evidence, если визуальной сводки недостаточно.

## 6. Выполните базовый ML-проход

![Вкладка Predictions с причинным правилом для ранних строк](assets/ui-ml-predictions.png)

Используйте вкладки строго слева направо:

1. **Features** публикует point-in-time признаки из ReplayPack.
2. **Universe** задаёт допустимые строки.
3. **Labels** публикует training-only исходы.
4. **Training** создаёт один неизменяемый model bundle.
5. **Model schedule** фиксирует момент доступности модели.
6. **Predictions** применяет расписание к признакам.

Каждый этап использует точные ID предыдущих артефактов. Обучение может брать
ранние строки ReplayPack, хотя готовой модели в тот момент ещё не существовало.
В **Predictions** выберите **No prediction before first model**: начальный
префикс останется без прогноза. Внутренние и конечные пробелы расписания всё
равно считаются ошибкой. То же правило префикса нужно выбрать в FirstSwap,
использующем этот PredictionSet.

Минимальный пример без источника запускается командой
`python -m backtest.examples.ml_baseline`; подробности — в
[базовом ML-примере](ml-baseline.ru.md).

## 7. Исследуйте связи кошельков

![Сводка исследования с точными счётчиками и предупреждением о качестве данных](assets/ui-research.png)

Исследование состоит из двух отдельных действий: подготовки ограниченного
snapshot и анализа сохранённого snapshot. Пустой список подписантов означает
всех наблюдавшихся подписантов внутри снимка, а не все кошельки сети. В заголовке
результата фиксируются окно, порог, область подписантов и режим токенов.

Не игнорируйте предупреждения качества. Строки без доказательства создания
остаются явной проблемой и не превращаются молча в обычные наблюдения.

![Граф связей кошельков из сохранённого синтетического результата](assets/ui-research-graph.png)

- Узлы — кошельки, ребро — наблюдавшаяся пара, прошедшая условия.
- **Current page** использует текущую страницу таблицы, **Whole result** — весь
  ограниченный результат.
- Порог отображения скрывает ребро только визуально и не пересчитывает группы.
- Выберите кошелёк или группу, затем откройте исходные покупки для проверки связи.
- Перед выводами проверьте вкладку **Data issues**.

Результат исследования остаётся артефактом гипотезы и доказательств. Он не
становится автоматически стратегией, ML-признаком или разрешением исполнения.

## 8. Проверьте артефакты и ресурсы

В **Artifacts and lineage** откройте артефакт по ID, проверьте digest и его
полный граф зависимостей. Не редактируйте файлы в data root вручную:
изменённый или незавершённый артефакт проверку не пройдёт.

В **Resources** показаны ограничения памяти, процессов, временного хранилища и
диска. При отказе по ресурсам уменьшите ограниченную область задания или
осознанно измените локальную конфигурацию. Повторное нажатие кнопки запуска не
обходит admission.

## Частые проблемы

| Симптом | Что проверить |
| --- | --- |
| UI открылся, но source inspection не работает | Настройте профиль источника и secret reference; самому UI live source не нужен. |
| Кнопка отправки недоступна | Заполните обязательные поля и используйте тип/версию артефакта из выбранного контракта. |
| Задание есть, ссылки на результат нет | Откройте **Events**: результат публикуется только после `SUCCEEDED`. |
| Вместо числа показано `—` | Метрика для результата недоступна; это не ноль. |
| Для ранних ML-строк нет прогноза | Выберите **No prediction before first model** и совпадающее правило инференса. |
| Граф меньше таблицы | Проверьте режим page/whole result и display threshold; скрытые рёбра остаются в evidence. |

Точные аналоги действий в командной строке описаны в [справочнике CLI](cli-reference.ru.md),
а настройки безопасности и источника — в [конфигурации](configuration.ru.md).
